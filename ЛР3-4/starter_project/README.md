# Расчёт стоимости заказа

Практические работы №3 и №4. Озеров Максим Дмитриевич, ЭФБО-11-25.

Последние две цифры зачётной книжки — 51. Вариант: `51 % 8 + 1 = 4`.
Учебная ставка НДС — 25%, максимальная скидка — 30%.

## Запуск в Windows

Откройте `run.bat` двойным щелчком и введите по одной строке: количество, цену, скидку.
Цена и скидка принимают десятичную точку или запятую. Пустые значения отклоняются.

В консоли из этой папки:

```text
java -Dfile.encoding=UTF-8 -jar OrderCalculator.jar 2 100 10
```

Ожидаемый итог — 225,00 руб. Ставка задана вариантом и не передаётся пользователем.
JAR уже собран. Для запуска достаточно Java 8 или новее, JDK не требуется.

## Проверки

`run_selfcheck.bat` запускает исходный SelfCheck и дополнительный BoundaryCheck из готового JAR.
Ожидаемый вывод: `PASS` и `PASS 48 checks`.

Доказательства фактической проверки находятся в `evidence`:

- `verification.json` — версии среды и сводка проверок;
- `cli_results.csv` — 27 консольных сценариев с фактическим кодом завершения и суммой;
- `example_output.txt` и `error_output.txt` — успешный и ошибочный запуск;
- `compile.txt` — результат компиляции.

Проверено на JDK 25.0.5.1 и JRE 1.8.0_51. Исходный SelfCheck сохранён побайтно.
Количество 0, цена <= 0, скидка > 30, NaN, Infinity, неверный формат и EOF вызывают ошибку с кодом 2.
Успешный запуск завершается с кодом 0. Повторный запуск выполняет независимый расчёт: программа не хранит состояние.

## Повторная сборка

Требуется JDK 17 или новее. Запустите `build.bat` из этой папки либо выполните:

```text
javac -encoding UTF-8 --release 8 -d out src/ru/edu/pr01/OrderCalculator.java src/ru/edu/pr01/SelfCheck.java src/ru/edu/pr01/BoundaryCheck.java
jar cfe OrderCalculator.jar ru.edu.pr01.OrderCalculator -C out .
```

Сборка не удаляет исходные файлы и не требует Maven или сетевых библиотек.

## Структура и соответствие заданию

- `src/ru/edu/pr01/OrderCalculator.java` — валидация, формулы, Scanner и вывод;
- `src/ru/edu/pr01/SelfCheck.java` — исходный контроль преподавателя;
- `src/ru/edu/pr01/BoundaryCheck.java` — 48 дополнительных проверок;
- `data/sample.csv` — исходные данные без изменений;
- `DECISIONS.md` — два ключевых решения;
- `../../Диаграммы/calculator_activity.*` — уточнённый алгоритм;
- `../../Диаграммы/calculator_classes.*` — диаграмма всех классов проекта.

Четырёхаргументный `calculateTotal` допускает явно заданную ставку и сохраняет исходный тест со ставкой 20%.
Трёхаргументный метод и пользовательский интерфейс используют `VAT_RATE = 25.0`.
`double` выбран согласно учебной цели; промежуточные результаты не округляются, отображение имеет два знака.
Для реальной финансовой системы нужен `BigDecimal` с определённой политикой округления.
