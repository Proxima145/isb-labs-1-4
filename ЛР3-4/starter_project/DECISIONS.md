# Два принципиальных решения

## 1. Арифметика и округление

Сохраняю `int` для целого количества и `double` для цены, процента и промежуточных сумм,
поскольку методичка закрепляет именно эти средства языка. Не округляю результат каждого шага:
два знака задаются только при форматировании вывода. Проверяю конечность чисел до расчёта.
В денежных системах вместо этого требуется `BigDecimal` и согласованная политика округления.

## 2. Параметр варианта и совместимость

Вариант равен `51 % 8 + 1 = 4`, поэтому в одном месте задаю `VAT_RATE = 25.0` процентов.
Сохраняю общий метод с четырьмя аргументами для исходного SelfCheck и добавляю перегрузку
с тремя аргументами, которую использует пользовательский запуск. Так исходный тест со ставкой
20% остаётся неизменным, а фактический расчёт варианта всегда использует 25%.
